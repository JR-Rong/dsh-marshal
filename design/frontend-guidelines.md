# Frontend Guidelines · Marshal Mobile Node

## 0. 元信息
- **版本**：v0.7.6
- **日期**：2026-11-20
- **状态**：approved & implemented（v0.7.6 已落地，见 `mobile/docs/ACCEPTANCE-v11-apple.md`）
- **目标端**：iOS（iPhone 14 Pro Max / iOS 27.2+）与 Android（ALT-AL10 / Android 12+）双端原生壳移动应用
- **Design Read**：这是面向单人掌控多机 AI 智能体集群的移动端 Node 控制台（设备与 Hub 连接、实时会话与审批、跨设备群聊、节点设置），给高标准移动办公与工程指挥者，语言是克制、通透、高密可读且具苹果硬件级精工感，倾向 Apple 原生 iOS HIG 现代风格族。
- **主参考**：Apple Human Interface Guidelines（iOS 26/27 · Liquid Glass 浮层 + Inset Grouped 内容层）+ `apple/DESIGN.md`
- **辅参考**：`plugin-build/icon.svg` 品牌色（Marshal Beacon Blue `#1F6FEB`）
- **置信度**：0.88

## 1. 设计目标与受众
- **一句话目标**：让皇上在手机上像操作 Apple 原生系统应用（如「家庭 / 捷径 / 信息 / 设置」）一样，一扫二维码即以 Node 身份直连目标设备并统筹其关联 Hub 下的全部设备、会话与群聊。
- **三条成功标准**：
  1. 首次打开 1 步扫码完成「目标设备 + 关联 Hub」双连接，连接拓扑（本机 Mobile Node → 目标设备 → 关联 Hub）一屏读懂。
  2. 双端真机（iOS & Android）均达 Apple HIG 触控、排版与对比度标准：正文 ≥17pt、触控热区 ≥44×44pt、浅色与深色模式均满足 WCAG AA（正文 ≥4.5:1）。
  3. 应用图标 100% 忠实还原仓库现有 `plugin-build/icon.svg`（`#1F6FEB` 蓝底 + 三阶信号横条 + 顶灯圆点），不另造字标。
- **Non-goals（明确不做）**：
  - 不在手机端承载 Hub 服务端、不监听入站端口、不嵌入桌面 `/marshal` 网页。
  - 不做廉价的通用深色渐变控制台、不做霓虹发光/赛博朋克滤镜、不做自定义应用内主题色花哨切换（遵循 Apple HIG 随系统浅色/深色自动适配，仅保留系统语义对比）。

## 2. 设计表盘
- **VARIANCE = 3/10**：克制统一的 Apple 原生组件秩序，保持每屏同一套大标题导航 + 分组卡片 + 底部悬浮 Tab 栏结构，仅在「设备连接拓扑主卡」与「实时扫码取景层」投入品牌记忆点。
- **MOTION = 4/10**：仅在底部弹窗（Sheet）、视图推入、状态徽章切换与扫码捕获时使用苹果弹簧曲线（`cubic-bezier(0.32, 0.72, 0, 1)`，220–320ms），全程遵循 `prefers-reduced-motion`。
- **DENSITY = 5/10**：面向高频多设备/会话浏览的均衡密度——列表行留足呼吸感（行高 ≥52pt，组间 20pt，左右安全边距 16pt），信息通过主标题 + 副标题 + 右侧等宽数值/状态胶囊分层，不堆砌指标大字块。

## 4. 正面清单（MUST）
- **MUST-01 单一视觉焦点**
  - 规则：每屏只有一个核心焦点（如设备页的「目标设备与关联 Hub 拓扑卡」、扫码页的「居中取景框」、会话页的「流式消息流」），其余信息退居二级分组列表。
  - 判定：首屏截图最大标题与正文比 ≥1.8×；主按钮每屏最多 1 个填充色主 CTA。
  - 例外：审批/提问待处理卡片出现时允许作为顶部高优先级横幅与主内容并列。
- **MUST-02 苹果双层材质规范**
  - 规则：内容层（列表分组、设备卡、消息气泡、设置项）一律采用实底语义色；磨砂半透明（Liquid Glass）严格限定于悬浮底部 Tab 栏、吸顶导航栏与弹出 Sheet 顶栏。
  - 判定：CSS 中 `backdrop-filter` 仅出现在 `.nav-bar`、`.tab-bar`、`.sheet-backdrop`、`.qr-hud` 四类浮层选择器。
  - 例外：无。
- **MUST-03 自适应浅色与深色双外观**
  - 规则：所有颜色通过 `var(--color-*)` 语义 Token 驱动，随系统 `prefers-color-scheme` 自动切换，同时在两种外观下验证对比度。
  - 判定：正文对比度 ≥4.5:1（浅色 `#1D1D1F` on `#FFFFFF` = 16.9:1；深色 `#F5F5F7` on `#1C1C1E` = 15.8:1）；次要文本 ≥4.5:1。
  - 例外：相机实时扫码取景覆盖层恒为深色半透明以保证取景辨识度。
- **MUST-04 品牌主色克制使用**
  - 规则：全应用唯一品牌主色取自 `plugin-build/icon.svg` 的 Marshal Beacon Blue（浅色 `#1F6FEB`，深色 `#409CFF`），仅用于主 CTA、激活态 Tab、链接与聚焦环；状态色仅使用 Apple 系统绿/琥珀/红。
  - 判定：强调色在任意截屏面积占比 ≤12%。
  - 例外：启动页与 App Icon 背景使用完整的 `#1F6FEB` 品牌蓝底。
- **MUST-05 严格触控与安全区规范**
  - 规则：所有可交互控件热区 ≥44×44pt，控件间距 ≥8pt；顶部避开灵动岛/状态栏（`env(safe-area-inset-top)`），底部避开 Home Indicator（`env(safe-area-inset-bottom)`）。
  - 判定：自动/人工测量全部按钮、输入框、Tab 项高度 ≥44px；真机截图无遮挡与横向溢出。
  - 例外：文本内联微标签（不可点击）不受 44pt 限制。
- **MUST-06 字体层级与中文精排**
  - 规则：使用系统字体栈（`-apple-system, "SF Pro Text", "PingFang SC", system-ui`），建立 6 档字号（34 / 22 / 17 / 15 / 13 / 12px）；时间、Token 计数、设备延迟等数值一律启用 `font-variant-numeric: tabular-nums`。
  - 判定：源码与渲染计算样式不存在 <12px 文字；数字列纵向对齐。
  - 例外：无。
- **MUST-07 4pt/8pt 网格与 Inset Grouped 卡片体系**
  - 规则：间距采用 4/8/12/16/20/24/32pt 阶梯；圆角统一 4 档（胶囊 `999px`、悬浮容器 `24px`、分组卡片 `16px`、控件/按钮 `12px`）。
  - 判定：所有 spacing 与 radius 均引用 `tokens.css` 变量。
  - 例外：1px/0.5px 头发丝分隔线。
- **MUST-08 全状态完整设计**
  - 规则：每个核心视图必须完整实现 未配对/首次引导、加载骨架、在线正常、离线重连、空列表、报错可重试 六类状态。
  - 判定：原型与真机均可触发并截图验证每个状态，无白屏、无死路。
  - 例外：无。
- **MUST-09 清晰动词文案与零系统术语泄露**
  - 规则：按钮文案全部使用明确动词（如「扫码连接」「发送消息」「批准本次」「重新连接」）；错误提示说明原因与下一步操作；严禁将设计说明、TODO、内部变量名渲染到界面。
  - 判定：文本检查 0 条元说明/占位符/TODO 泄露。
  - 例外：高级排查页与诊断详情中允许展示 `deviceId`、Hub URL 等技术字段。
- **MUST-10 图标同源与矢量一致**
  - 规则：App Icon 与启动页标志直接由仓库 `plugin-build/icon.svg` 生成；界面内全部图标采用统一 SF Symbols 风格 1.75–2px 圆角描边/填充矢量 SVG，与相邻文字字重匹配。
  - 判定：图标生成脚本直接读取 `../plugin-build/icon.svg`；界面内不使用零散 Emoji 充当导航/功能图标。
  - 例外：智能体/设备自定义名称中原样包含的字符保留显示。
- **MUST-11 Token-First 跨端同源**
  - 规则：颜色、字号、圆角、阴影、动效时长全部定义于 `design/tokens/tokens.css` 并同步到 `mobile/src/styles/tokens.css`，业务样式禁止出现裸 hex 颜色与硬编码魔法字号。
  - 判定：CSS 漂移检查裸色值为 0（除 `transparent` / `currentColor`）。
  - 例外：`plugin-build/icon.svg` 内嵌品牌色及扫码相机取景纯黑底。
- **MUST-12 动效克制与无障碍兜底**
  - 规则：所有图标按钮均带 `aria-label`；状态不单靠颜色表达（辅以文案或图标）；支持 `prefers-reduced-motion: reduce` 与 `prefers-reduced-transparency: reduce`。
  - 判定：代码审计所有 icon-only button 具备 `aria-label`；媒体查询完整覆盖。
  - 例外：无。

## 5. 反面清单（NEVER）
- **NEVER-01 禁止紫蓝渐变/赛博霓虹 AI 味**
  - 禁止：在标题、按钮、背景中使用靛紫/洋红渐变或大面积霓虹发光阴影。
  - 为什么：典型 LLM 模板审美，违背 Apple 克制实体美学。
  - 判定：样式中无紫色系渐变与彩色外发光 `box-shadow`。
  - 例外：无。
  - 修复：回归纯中性底色 + 单一 `#1F6FEB` 品牌蓝。
- **NEVER-02 禁止内容层滥用毛玻璃**
  - 禁止：给普通设备卡、会话列表项、消息卡片、表单分组加 `backdrop-filter: blur(...)`。
  - 为什么：违背 Apple `liquid-glass.md` 双层原则，造成视觉浑浊与中端 Android 掉帧。
  - 判定：`backdrop-filter` 仅允许用于浮层导航/弹窗/扫码 HUD。
  - 例外：无。
  - 修复：改为不透明语义底色 `var(--color-surface)` + 细微头发丝边线。
- **NEVER-03 禁止用 Emoji 替代系统导航与功能图标**
  - 禁止：在 Tab 栏、标题栏、按钮、状态卡中用 📱/🤖/⚙️/🔗 等 Emoji 充当 UI 图标。
  - 为什么：跨 iOS/Android 渲染割裂且显得廉价，违背 Apple `icons.md`。
  - 判定：界面源码无 Emoji 图标占位。
  - 例外：用户消息正文与远端返回的名称原文。
  - 修复：全部改用统一线宽的 SF 风格 inline SVG 符号库。
- **NEVER-04 禁止另造 App 图标**
  - 禁止：手绘汉字「调」或其他重新发明的图标替代仓库自带图标。
  - 为什么：皇上明旨「应用图标直接使用当前仓库中已有的图标资源」。
  - 判定：iOS `AppIcon` 与 Android `mipmap-*` 均由 `plugin-build/icon.svg` 渲染产出。
  - 例外：无。
  - 修复：统一通过资源构建脚本从 `plugin-build/icon.svg` 生成全尺寸图标。
- **NEVER-05 禁止强制单深色皮肤与无意义主题色选择器**
  - 禁止：把 App 锁死在灰暗深色背景（如 `#151719`），或在首页放「蓝/紫/灰」花哨换肤按钮。
  - 为什么：Apple HIG（`dark-mode.md`）明确建议遵循系统外观并保持统一品牌识别。
  - 判定：默认支持系统浅色 + 深色双外观；首页无换肤控件。
  - 例外：如皇上在设置中需要强制浅/深预览，仅可置于高级设置项内（默认「跟随系统」）。
  - 修复：以 `prefers-color-scheme` 驱动完整浅/深色 Token。
- **NEVER-06 禁止大字数字 Hero KPI 仪表盘模板**
  - 禁止：在首屏堆砌 3–4 个大号渐变数字方块（如「01 / 02 / 03」装饰编号卡片）。
  - 为什么：生硬的后台大屏模板，不适合单手操作移动端。
  - 判定：设备首页只展示真实连接的「目标设备主卡」+「关联 Hub 节点列表」。
  - 例外：无。
  - 修复：采用 Apple Inset Grouped 分组列表与简洁状态行。
- **NEVER-07 禁止裸值硬编码与 <12px 极小文字**
  - 禁止：在组件样式中直接写裸 hex 色值或 `font-size: 10px / 11px`。
  - 为什么：破坏跨端一致性与移动端可读性。
  - 判定：静态检查无裸色值、无 <12px 字号。
  - 例外：`tokens.css` 定义文件本身与 SVG 品牌图标。
  - 修复：全部映射至语义 Token，最小辅助说明字号 12px。
- **NEVER-08 禁止以弹窗打断常规流程**
  - 禁止：启动即弹权限/登录 Alert，或把普通错误做成阻塞式 `window.alert`。
  - 为什么：违背 Apple `alerts.md` 与 `onboarding.md`，权限须在用户点击「扫码连接」时按需请求。
  - 判定：源码禁止出现 `window.alert` / `window.confirm` / `window.prompt`。
  - 例外：断开连接/清除全部凭据等不可逆破坏性操作，使用 Apple 风格确认 Sheet。
  - 修复：用内联状态条、轻提示胶囊（Toast）或底部操作表（Action Sheet）承接。
- **NEVER-09 禁止把链接或令牌明文泄露至 URL/日志**
  - 禁止：在界面明文展示或持久日志打印 `mph1.*` / `dashboardToken` / `deviceToken`。
  - 为什么：移动端安全底线；凭据仅入 iOS Keychain / Android 安全存储。
  - 判定：凭据输入框掩码显示，日志与 UI 仅显示脱敏指纹或连接状态。
  - 例外：无。
  - 修复：凭据经原生安全存储保管，配对码 60 秒一次性兑换。
- **NEVER-10 禁止只做 Web 壳套 iframe**
  - 禁止：用 WebView 直接加载 `https://<hub>/marshal` 网页敷衍了事。
  - 为什么：丧失原生交互、离线容错、原生扫码与安全存储，违背移动端 Node 架构要求。
  - 判定：全部界面由自绘 Apple 风格前端渲染，网络走原生 HTTP/SSE/WS 栈。
  - 例外：无。
  - 修复：原生壳 + 自绘苹果风格界面 + 原生流式与扫码能力。

## 6. 交付范围
- **端**：iOS（Capacitor 7 + SwiftPM 原生工程 + `MarshalStream` Swift 插件）& Android（Capacitor 7 + Gradle/JDK 17 + Android SDK 35 + `MarshalStream` Java 插件）
- **核心屏清单**：
  1. **首次连接 / 扫码引导屏（Connect）**：Marshal 图标主视觉 + 唯一主 CTA「扫码连接目标设备」+ 展开式「手动输入 / 粘贴配对码」
  2. **实时扫码取景层（Scanner）**：全屏原生相机取景 + 苹果风格圆角取景框 + 闪光灯开关 + 从相册识别二维码 + 手动输入入口
  3. **设备与 Hub 总览（Tab 1 · 设备）**：本机 Mobile Node 身份条 + 已扫码直连的目标设备主卡（含直接桥接状态 & Agent 列表）+ 关联 Hub 集群设备分组列表 + 快捷「切换/扫码」
  4. **会话与实时交互（Tab 2 · 会话）**：按设备/Agent 筛选会话 + 会话详情（流式回复、工具调用折叠、审批/提问内联卡片、底部附带模型/思考强度/附件弹窗的输入栏）
  5. **群聊与协作（Tab 3 · 协作）**：分段控件切换「跨设备群聊」与「任务看板/记忆/花名册」——支持查看群聊、实时发言/停止、新建群聊、看板与只读记忆浏览
  6. **节点与设置（Tab 4 · 设置）**：本机 Mobile Node 信息、当前目标设备 & Hub 连接诊断、重新扫码配对、6 位 PIN 应用锁、外观设置（默认跟随系统）、安全断开
- **状态清单**：未连接、扫码中、连接中/骨架、在线正常、离线自动重连、空状态、错误可重试
- **视口与外观**：紧凑屏（375–430pt，含 iPhone 14 Pro Max 430×932pt 与华为 ALT-AL10 360×834dp）、横屏适配、浅色 + 深色双主题

## 7. 变更授权与流程
- 任何触碰色彩/字体/组件契约的修改，须先更新本文件版本号并记录于 `design/decision-log.md`，再改 Token 与实现。
- 每次 UI 改动后执行：Token 漂移自检 + 单元测试 + 双端构建 + 真机/截图验收。

## 8. 验收定义
- **客观项**：
  - TypeScript 类型检查 & 单元测试全通过（0 error）
  - 静态扫描：0 条裸色值漂移、0 条 `window.alert`、0 条 Emoji UI 图标、最小字号 ≥12px、触控热区 ≥44px
  - 桌面端生成目标设备 + Hub 二维码 → 手机端扫码解析并完成目标设备与 Hub 连接闭环（含自动与实机测试）
  - Android 真机（华为 ALT-AL10）安装、启动、截图实测通过；iOS 真机（`siyao的iPhone`，在开启开发者模式与签名后）或模拟器安装、启动、截图实测通过
- **主观项**：皇上审阅真机截图与交互手感签收。
