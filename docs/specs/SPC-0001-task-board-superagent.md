# SPC-0001 · 任务看板人工派发桥（Super-agent Dispatch Bridge）

- 状态：已批（皇上 2026-11-18 钦定五项）
- 风险级：P2
- 提出与批准：皇上 / 丞相
- 关联 ADR：ADR-0001
- 任务包：TASK-0001

## 1. 目标

皇上在任务看板 GUI 新建一张工单后，系统自动唤醒皇上指定的一个智能体，让它在**该工单的原生执行会话**里完成开发；工单内容、执行会话、状态与结果都留在看板。工单结算后，把这次工作的摘要写入该智能体的长期记忆，下次派发前再取回参考。

不做会怎样：每张工单仍要人工点 Run、手动把内容转给某个 agent；多任务上限仍是人的注意力，正是 Super-agent 要解决的问题。

## 2. 范围

本次在 dsh-marshal 插件内新增 superagent 模块：

1. 浏览器端观察任务看板的「新建卡片」请求；只有 GUI 的人工新建会通知主机。
2. 主机端解析默认 agent 与卡片标签（@某官）覆盖，读取 ~/.dsh/dsh-agents/ledger.json 的成员定义。
3. 在卡片首次执行前，把 agent 身份 / 职责 brief / 相关长期记忆 / 工单要求合成执行提示，并补齐该成员的权限、模型、思考档位、Agent 预设（不超过看板会话默认权限）。
4. 通过看板原生执行入口自动 run；卡片进入 Running，执行会话可从卡片打开。
5. 执行结算后，把结果与工作摘要写入该成员 agent 作用域的长期记忆；卡片上写回派发元数据。
6. 提供 marshal_superagent 工具：status / config / agents / dispatch（人工补派）/ reconcile。
7. 状态与设置存 ~/.dsh-marshal/superagent/，原子写、限长、可关闭。

## 3. 不做

- 不改第三方看板（@linxin666/dsh-client-ui-task-board）与智能体（@linxin666/dsh-agents）源码。
- 不做 LLM Router 自动决策；默认 agent + 标签覆盖是确定性规则。
- 不做手机 / 远端 GUI 的自动触发；v1 只认本机浏览器。手机建卡可用 marshal_superagent dispatch 补派。
- 不自动确认高于会话默认权限的授权；不绕过看板的权限闸门。
- 不做追问转发、群聊、跨设备派发；这些是后续增量。
- 不替换现有 dispatch 台账、groups、memory 逻辑。

## 5. 非功能

- 依赖：不新增 npm 运行依赖；只用 Node 内置与现有 DSH 服务。
- 降级：看板 / 记忆 / dsh-agents 账本缺失时功能自降级，插件其余能力不受影响。
- 时延：人工建卡到派发 ≤ 2s（本机）；派发不阻塞看板响应。
- 可靠性：状态文件原子写；派发记录上限 500；重复通知幂等；重启对账。
- 安全：路由仅本机同源；不自动确认权限；不把 token/密钥写入卡片或记忆；记忆注入截断。
- 隐私：记忆为本地存储；注入到卡片 prompt 的内容有上限；可在记忆页删除。
- 兼容：DSH ≥ 0.2.2-rc.3；看板扩展契约 v1；dsh-agents 账本 schema 不变。

## 6. 约束与未知

- 看板没有「卡片创建」事件，也不存创建者。触发只能从浏览器端观察 POST api/task-board/action 的 create；这是本方案唯一依赖的第三方实现细节，若看板改端点则 hook 失效并降级为不触发。
- 看板原生执行会话不是 dsh-agents 成员 run，记忆身份不会自动解析到成员；所以桥接层显式读写该成员记忆，而不是依赖自动摘要。
- 成员权限若高于看板会话默认权限，桥接层不自动确认，只记录并让皇上在看板 UI 确认。
- 远端/手机建卡不触发；用 marshal_superagent dispatch <taskId> 补派。

## 7. 风险与回退

- 最高风险：浏览器 fetch 监听影响看板请求。缓解：hook 只旁路观察、始终返回原 Promise、异常吞掉、单测覆盖；不命中端点就完全不动作。
- 误唤醒：默认 agent 配置后所有人工新根卡都会唤醒。缓解：可清空默认、加标签覆盖、速率限制、enabled 开关。
- 记忆污染：只写 episode 类、带 taskId 标签、限长；可在记忆页删除。
- 回退：重新安装上一版 dsh-marshal-0.2.0-agent-groups.2.tgz；状态目录独立，不迁移、不删既有数据；删除 ~/.dsh-marshal/superagent/ 即清空派发记录。
