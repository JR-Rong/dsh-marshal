## 1. 计划使用方式

v0 已有可构建的插件、源码、测试和 DSH 接缝记录。[原实施计划](2026-10-29-marshal-v0.md) 保留历史；本计划只规定剩余缺口、回归与升级。ACK 分派、hub 同键并发合并、node deadline、事件身份校验和重连快照已有实现，不能将它们标为“尚未编写”。逐项证据见 [基线复核](../specs/2026-10-29-marshal-acceptance.md#0-评审基线与已有证据)。

P1 优先改动：ACK 来源/当前连接绑定 → node 幂等与结果未知 → 全通道隐私 → 原子同步及待答恢复。稳定 deviceId、wire v2、登录 cookie 等涉及兼容性，必须连同公共契约 §1.1 的迁移完成，不能只改文档默认值或局部上线。

每个任务先核对已有代码/真实接口，再做最小实现，运行列出的验证，记录实际输出。文件表区分已有模块修改和新增模块；先复用现有测试与工具。未来单元测试使用合成输入，协议 fixture 必须从固定版本真实采集并脱敏；不允许同时编造接口和证明它正确的 fake。

仓库已经初始化，不再 git init。不自动 commit/push/建 PR/部署；是否执行这些动作取决于届时任务授权。复选框仅追踪本轮增量与回归，不否定历史已实现工作；直到对应新增验收证据成立才勾选。

## 2. 依赖与执行顺序

V0-T00 → V0-T01 → V0-T02 → V0-T03 → V0-T04 → V0-T05 → V0-T06 → V0-T07 → V0-T08 → V0-T09 → V0-T10。
