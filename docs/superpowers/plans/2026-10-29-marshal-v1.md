## 1. 执行原则与依赖

基线 `feat/v0@702ef24` 已实现 v0 ACK 路由、内存去重、deadline、事件身份校验及重连快照。先完成 [v0 P1 增量计划](2026-10-29-marshal-v0-p1.md) 中剩余的 ACK 来源绑定、node journal、隐私、原子同步及 wire v2 迁移，再接新 agent。原计划中的复制式 SDK/协议实现全部由本版任务契约取代；不得从旧稿复制本会话授权、请求值回读、按目录索引收紧和无条件 resume。

主顺序：V1-T00 → V1-T01 → V1-T02 → V1-T03 → V1-T04 → V1-T05 → V1-T06 → V1-T07 → V1-T08 → V1-T09 → V1-T10。Codex 先完成基本链路，再以同一公共边界接 Claude；未通过的能力只读/关闭，不堵住其它 agent。

跨层验证采用 v0 计划的规则：前置任务先给组件证据，依赖尚未完成的 I 层用例明确延期到 V1-T09，R 层到 V1-T10；不能循环要求前置任务通过依赖后续 UI/适配器的全链路验证，也不能预先勾选通过。

所有文件名为未来改动面；runner 等已有模块须复用，journal/privacy/sync/inputs 依赖 v0 增量任务先交付，目前并不存在。实际任务先读对应现有代码，再决定最小变更。测试按 U/I/R 分层，所有复选框目前未执行。不会因为执行计划文本就自动提交、推送、创建 PR 或部署。
