# DSH 0.2.2 seams observed in production

These are host behaviors that differ from the obvious API shape. They are
recorded so the next contributor does not rediscover them.

## Session prompt

`ctx.sessionController.prompt(request, signal)` takes a second
`AbortSignal` argument. Passing only the request object ends in
`Cannot read properties of undefined (reading 'throwIfAborted')`.
Keep a plugin-lifetime `AbortController` and pass `controller.signal`.

## Turn state

Do not read `controller.activeTurn`; SessionController does not expose it.
Read `controller.list()` and inspect the target session's `running` flag.
The marshal surface already wraps the native follow/list shapes.

## Tool render

A tool's `output.render` is called as `render(args, value)`, not
`render(value)`. If the signature is wrong, list actions can silently
render the JSON arguments (`{"action":"list"}`) while reporting success.

## Missing host services

DSH 0.2.2 does not provide `taskBoard` or a `/dsh-agents` API by itself.
- task board: install the task-board plugin, or use marshal's local
  fallback board (`taskBoardSource: "local"`);
- agents: install `@linxin666/dsh-agents`; marshal's agent page and tools
  intentionally fail with a readable "backend missing" message otherwise.

## Panel ids

`ctx.layout.selectPanel(id)` throws when `id` is not registered.
`openPanel('task-board')` is a no-op when the native board is absent;
the panel now falls back to its own tasks tab.

## Health

`GET /marshal/health` is intentionally same-origin-open on loopback and
reports which capabilities are actually mounted. Use it before debugging
individual routes.
