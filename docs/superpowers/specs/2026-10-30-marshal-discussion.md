# dsh-marshal 跨平台讨论组设计（D1）

日期：2026-10-30

依据：[总体设计](2026-10-29-marshal-design.md) · [公共契约](2026-10-29-marshal-contract.md) · [插件参考调查](../spikes/2026-10-30-orchestration-references.md)

## 1. 产品边界与进入条件

用户选择来自不同设备/平台的 agent、议题和允许共享的材料，启动有限轮次的讨论，获得带出处的共识、分歧、待确认事项和行动建议。讨论可用于方案比较、设计评审等，不自动落地建议。

D1 在 v1 认证、node journal、真实控制边界、隐私及恢复门槛完成后实施。它不改变 v0/v1 的承诺，也不阻塞现有 P1 加固。至少两个不同原生平台通过验收才宣称“跨平台讨论”；多个 DSH provider/model 只能证明 DSH 内部讨论。

- 首版仅一个 owner；没有多人组织权限、外部群聊连接或对其它人的消息发送。
- 每个成员使用全新、独立的讨论会话；选择已有 agent 身份/平台不等于加入其现有工作会话。首版不 fork、resume 或自动导入工作会话历史。
- agent 只产生文字分析和汇总。讨论中的任务建议不会进入执行队列，不启动代码修改、终端、联网工具、审批或子 agent。
- 用户另行发起执行才进入原有控制流程，重新确定目标、权限与幂等键；讨论消息不构成执行授权，也不携带原生审批卡。

## 2. 用户流程

1. 新建草稿：填写议题，选择 2–4 个成员（设备、原生平台、精确模型/版本、角色），指定一名成员在讨论结束后汇总。
2. 预览：展示会发送给哪些设备及其配置的模型服务、正文片段、轮次、时间/调用上限和原生会话可能保留记录的事实。该确认仅授权这次讨论所需的模型调用与成员间共享。
3. 开始：校验每个成员的能力和本地授权，创建专用无工具会话。失败则保持未开始/失败；不偷偷换 provider、模型或成员。
4. 第一轮独立给出意见；后续轮次读取上一轮已封存的共同记录，交叉评论。UI 显示发言来源、原生完成证据、未回复或失效成员。
5. 汇总：分别列出共识、分歧、证据与未知项，引用 messageId；未完成者明确缺席，不把沉默当赞成。用户据此决定后续行动。

房间启动后成员、资料和策略冻结。改议题、增删成员或追加材料需要用户创建新的 run，重新展示共享范围与预算；不在后台延长当前运行。

## 3. 架构与复用

```text
用户 → hub RoomCoordinator（成员、轮次、预算、记录与展示）
          │ 复用认证连接、写命令幂等、状态查询及隐私投影
          ├→ node DiscussionSession → DSH 专用会话
          ├→ node DiscussionSession → Codex 专用会话
          └→ node DiscussionSession → Claude 专用会话
```

hub 是唯一调度者，成员不能直接互相发控制命令。每个 node 仍是执行去重、原生隔离和实际状态的权威。不得由 hub 直接调用第三方模型绕过 node 策略。

| 责任 | 复用与增量 |
|---|---|
| RoomCoordinator | 新增房间/轮次状态机、预算预留与封存记录；固定规则调度，不接受模型生成的调度代码 |
| DiscussionSession 适配端口 | 在已有 AgentHost/surface 内验证 create/submit/observe/interrupt/dispose；无现成无工具新会话能力时不开放该平台 |
| 身份与命令 | 复用 operatorId、deviceId、runtimeEpoch、journal 与 ACK；房间控制命令扩展判别 schema，不能透传任意原生方法 |
| 内容与页面 | 复用源端白名单、设备策略、纯文本/SSE/背压；讨论记录与原生 PendingInputs 分开，后者不允许加入讨论 |
| DSH 原生协作机制 | 参考 Agent Team 的身份/投递与 dsh-agent-teams 的代次/调度；是否调用窄公共接口由 D1-T00 决定，不默认挂载整个 profile |

未来路径建议为 `src/hub/discussions/`、`src/agents/discussion.ts` 与现有 wire、runner、privacy、api/page 的最小扩展。以上均未创建；不另建重复的认证、journal 或适配器进程监督器。

## 4. 讨论权限与内容授权

“仅讨论”必须由原生能力和宿主隔离强制执行，不能只靠 system prompt。新会话需要已验证的工具禁用：无文件/终端/网络工具、MCP、技能执行、子 agent、用户自定义启动 hook 或自动恢复工作任务；模型服务的正常推理请求除外。若宿主不能保证这些条件或创建会话就会执行不可隔离的 hook，标 `discussion-unavailable`，不以“工具申请时再拒绝”替代禁用证据。

本地新增默认关闭的 `allowDiscussion` 授权（node 本地配置与 hub 设备记录均须 true），不由浏览器开启。各参与设备还须满足现有 content 双授权。hub 的该授权变化加入同一持久 policyRevision。每个 run 的 owner 确认绑定 participant 列表、provider/model、材料摘要和策略修订；普通 allowContent/allowInteractions 均不自动授权把内容再次发给别的 agent。汇总者与其它成员同等授权。

只共享 owner 预览确认的粘贴文本或显式选择的、经允许的历史片段，以及本 run 的讨论输出。历史选择仍经过公共契约 §10 过滤；原生提问、审批、secret 和结构化答案不得作为材料。首版不抓取附件/URL、不自动读取 cwd/仓库/完整历史。所有成员知道这些内容会交给列明的模型服务；不承诺原生 runtime/provider 无日志或零保留。

跨成员转发必须同时满足发送方当前出站授权、所有接收方当前讨论授权和该 run 的共享清单。每条成员输出标为不可信引用数据；其中“忽略规则”“执行命令”“添加成员”等文字不能修改房间配置、预算或工具权限。消息实际作者取认证 device/session 绑定，不能相信正文或帧自报名称。

运行中任一成员授权、模型配置或 runtime 变化即暂停整个 run，停止新分发，清空本 run 的正文（含派生汇总）并通知所有浏览器清空；源端尽力取消已接纳调用。新策略经用户重新确认才能使用全新专用会话开始新 run，不复用已收过撤权内容的旧讨论上下文。无法撤回已经送达其它模型/已被人看到的内容，不宣称清缓存等于撤回披露。

## 5. 调度、身份与预算

`roomId` 是持久元数据身份；每次显式运行生成 `runId`，绑定当前 `hubEpoch` 和各成员的 `(deviceId, agent, sessionId, runtimeEpoch)`。每条调度命令绑定 runId/roundId/memberId/turnId/idempotencyKey；新会话创建尚无 sessionId 时沿用公共契约 create 的 null target 语义。服务端签发 messageId 和单调 roomSeq，保存 replyTo/sourceMessageIds；来源不可由模型伪造。

房间状态为 draft → preparing → running → summarizing → completed；任何活跃状态可转 pausing → paused、stopping → stopped 或 failed。停止/暂停先原子关闭新分发，再取消已接纳调用；直到源端确认不再运行才进入相应终态，否则显示结果未知。completed 只表示讨论及汇总完成，不表示建议已经执行。

首版固定轮次：一轮内各成员最多发言一次，可并行；下一轮只消费上一轮封存的同一份记录，不能边输出边无限触发其它成员。一个原生会话最多一条在途调用；busy 不进入延迟队列。成员超时/错误留出缺席项，不自动重试或由另一模型冒名补位。只有已确认终止的失败成员可跳过后继续；取消/结果未知则 run 暂停，不能边猜测边启动下一轮。

| 预算 | 首版上限与达到后的行为 |
|---|---|
| 成员/轮次 | 2–4 名成员；1–3 轮，由 owner 开始前选择；首版不得扩大 |
| 推理调用 | 最多成员数 × 轮数 + 1 次汇总，最多 13 次；失败和超时也消耗名额，不补发。创建会话必须已证明不隐式推理 |
| 并发 | 每 run 最多成员数个在途调用；hub 最多 4 个活跃 run，每成员会话仅属于一个 run |
| 时间 | 单次调用 120s，整个 run 15min，单调时钟；超限停止分发并请求取消 |
| 正文 | 单次输入 64 KiB、输出 16 KiB UTF-8；房间 4 MiB，所有房间合计 16 MiB，并共享公共契约的 hub 内容 64 MiB 总预算；超限停止，标不完整，不静默截断后宣称完整结论 |
| 保留 | 仅 hub RAM；结束/暂停后最多 15min，活跃期亦受整体期限和字节上限；到期、关闭或撤权清理，不落磁盘/IndexedDB/正文日志 |

首次分发前原子预留调用名额；创建/轮次/汇总使用稳定的写命令键并通过 node journal。ACK accepted、完整原生 turn 结束、消息被选入下一轮是三个不同状态。只有完整且已校验的最终输出进入封存记录；未完成增量仅供预览，不当作已完成意见。

时间/调用数限制不等于硬金额/token 限制。适配器如有已验证的输出 token 上限可叠加；无用量回读时显示“用量未知”，不能用字符数冒充真实 token/费用。取消请求发出后 provider 可能仍产生费用；源端不可达或无法确认取消时必须保留未知状态。

## 6. 恢复、汇总与生命周期

房间元数据 journal 只保存 owner、成员绑定、run/round/命令 ID、预算预留、状态和材料的带密钥摘要，不存议题/材料/发言/汇总正文。启动/分发前先持久化相关元数据，再调用现有 node journal；单 hub 实例对该状态持有排他锁，多实例不竞跑同一房间。

hub 重启不恢复自动调度；旧 run 标 paused/outcome-unknown，查询原命令状态但不重发。没有正文就不能重建原讨论或自动重新汇总。用户必须核对未知调用，再显式以材料重新预览启动新 run；清除旧未知不作为启动的捷径。node/runtime 重启、设备离线或协议版本改变同样撤销原成员绑定，不偷偷创建替代会话。普通页面重连在 hub RAM 仍有效时用快照+游标恢复展示，不能再次发起讨论。

正常汇总由预先选定成员额外调用一次，继续无工具限制和剩余预算；只能引用本 run 的封存 messageId。汇总中引用不存在的 ID 标无效；意见内容是否准确仍需用户判断，不能把 ID 校验包装成事实验证。失败/额度耗尽/缺少安全汇总能力时保留带缺席标记的原发言列表及“汇总未完成”，不自动增预算重试。

停止、到期、撤权和插件卸载均释放订阅、计时器、worker/会话句柄；不得删除原生用户工作会话。专用会话的原生持久历史依平台自身规则处理，在启动预览中披露；marshal 不承诺清除其记录。浏览器普通登出仅断开该登录会话展示，已授权的有界 run 继续；若要终止，使用明确的“停止讨论”。设备撤权则按 §4 暂停。

## 7. 验收标准

沿用公共验收的 U/I/R 分层，全部用例当前 **NOT RUN**。至少一个 R 组合为两个不同原生平台、分布在两台目标机器；未覆盖的平台/版本不得宣称支持。各故障测试检查原生调用次数、最终状态、正文出口与资源释放。

| ID | 层 | 场景 | 通过条件 |
|---|---|---|---|
| G01 | R | 固定 DSH/Codex/Claude 候选版本，验证专用会话和禁用工具 | 至少两个原生平台通过；不能禁用工具/hook 的平台 unavailable；同 DSH 多 provider 不算跨平台；记录准确版本及隔离证据 |
| G02 | U/I/R | 新建讨论、现有工作会话运行中、恶意发言要求执行/扩权 | 专用新会话；工作会话无 resume/fork/写入；终端/文件/网络工具、MCP、子 agent 调用均为零；原有全局配置不变 |
| G03 | U/I | allowDiscussion/content 各自缺一、参与方未确认、临时更换模型/provider | 任一缺失零正文分发/零推理；共享预览与实际成员/模型一致；更换须新 run 确认，不能自动降级或换人 |
| G04 | U/I | 并发开始、重复 HTTP、丢 ACK、hub 在登记/发送/落结果边界崩溃 | 一个 run/命令最多一次原生调用；稳定键、预算预留与 node 去重协作；未知只查询，重启不自动重发/重建会话 |
| G05 | U/I | 消息伪造作者、旧 run/成员 epoch 迟到、重复输出与乱序增量 | 作者来自认证绑定；旧代次不进入当前讨论；一个完成发言一次入封存记录，下一轮所有成员读取同一记录 |
| G06 | U/I/R | 第三轮结束、调用额用尽、长回合、超长输出、多个房间满额 | 名额/时间/正文/全 hub 预算均不超界；停止新调度；无无限互相唤醒；不把字符数或请求取消当硬费用/执行停止证明 |
| G07 | I/R | 成员掉线、busy、超时，取消确认与未确认分别注入 | busy 不排队，故障不自动重试；已终止成员可标缺席；未知则暂停、不发下一轮；其它 agent 的非讨论会话不受影响 |
| G08 | I/R | 用户停止、设备撤权、策略/runtime 变化、插件卸载 | 原子禁新分发，旧回复不污染后续 run；取消未确认仍未知，确认后停止；授权收紧清理相关正文，资源释放且无后台重启 |
| G09 | U/I | 合成秘密/原生审批和答案藏在 history/tool 派生材料；模型指令注入；脚本文本 | 已知交互正文不进入材料/磁盘/日志；非白名单阻断；正文纯文本，不能改权限、成员或调度；明确无法撤回已送达模型的内容 |
| G10 | I | 浏览器重载/游标丢失、hub 重启、RAM 过期、元数据状态损坏 | 页面恢复不触发调用；重启无正文不伪造原记录，旧 run 暂停/未知且零自动汇总；损坏拒绝新运行、人工恢复 |
| G11 | U/I/R | 意见冲突、成员缺席、汇总错误引用/失败/额度耗尽 | 共识/分歧/未知分列；引用仅限存在且可见的封存消息；缺席不算赞成，错误引用标无效；无虚假完整汇总、无执行任务产生 |
| G12 | I/R | 完整运行后停用插件，重复装载；检查持久化与依赖影响 | timer/listener/worker 无泄漏；marshal 磁盘无正文；原生保留行为已披露；未挂载会改变全局控制的 profile，许可证及固定版本依赖有记录 |

关闭条件：设计、实施计划、适配器能力报告和 G01–G12 证据对应；真实禁用工具、跨平台链路和恢复门槛缺一则不发布跨平台讨论能力。文档通过不等于功能已经可用。
