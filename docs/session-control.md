# 已有会话的接管与继续

2026-10-31 按实际使用需求补充：本节替代旧 v1 文档中“外部历史会话始终只读”的产品限制。旧设计的跨进程排他要求仍不应被误报为原生 resume 已经提供。

- 查看/选择/订阅继续保持只读，不调用 resume，不启动 Query，不生成推理。
- Codex 与 Claude 的已有会话提供“接管并继续”和“接管并发送”。首次发送先 acquire，收到源端可写能力确认后才提交 prompt；失败或不确定时保留草稿，不重发。Codex 使用原 thread ID 调用 thread/resume；Claude 以原 session ID 和工作目录建立恢复 Query。身份不一致则拒绝，不用 fork 或新建替代。
- 已恢复的会话标记为 attached，表示已取得本地原生运行时的控制句柄；它不表示其他终端/桌面已经关闭或被锁住。界面提示避免并发向原会话发送，不自动终止其他窗口任务。
- 本实例创建的会话继续使用 ours；未恢复会话可以输入首条消息并触发接管；未验证和已知运行中的会话仍不开放写入。attached 与 ours 均继续受能力、同步屏障、幂等 journal、运行时代次和回合状态约束。
- DSH 已连接同一宿主的 SessionController，使用 attached；普通发送由原生宿主恢复原会话并受理，不需要另起模型进程。已知忙碌仍拒绝普通发送。
- 原生运行时退出或插件重载后，Codex/Claude 不自动恢复写权；用户可再次显式接管已有会话。恢复不自动重发旧消息。
- 周期扫描允许更新最近输入时间相同的运行状态：DSH 完成回合通常不改变 updatedAt。扫描期间到达的新回合事件优先，避免旧快照清掉新任务。
- Hub 重启或网络重连后，以新采集的能力快照替换旧连接状态；健康能力不会继承断线时的 stale 标记。匹配的同步 ACK 到达前仍禁止写入，故障源保持不可用。
- Claude 未登录返回 auth-required；不假定存在历史文件就能调用模型。Claude SDK 不提供跨进程运行状态，无法承诺拒绝另一个终端中的所有并发运行。
- 插件对当前原生运行时串行提交指令；不把该互斥说成跨进程锁。

实现复用既有所有权协调器，以 evidence.scope=native-runtime 区分恢复控制范围，并在节点隐私投影、Hub 能力投影和页面保留 attached。未知所有权值仍被丢弃；旧 Hub/页面不认识该状态时保持只读，先部署 Hub/页面再更新节点。

参考：[Codex App Server 的 thread/resume](https://learn.chatgpt.com/docs/app-server#start-or-resume-a-thread)、[Claude SDK 会话恢复](https://code.claude.com/docs/en/agent-sdk/sessions#resume-by-id)。接口可恢复历史不等于跨进程独占，这是本实现明确保留的边界。

单会话正文流：DSH follow 必须显式传 assistantStream=true，否则原生默认只提供持久事件而不提供实时文本。节点 privacy=content 与 Hub allowContent 同时开启才同步正文；当前双机安装已按继续对话需求启用，仍保留凭据脱敏。界面按 itemId 聚合流式正文并显示用户消息，正文只保留在内存；同一 Hub/节点/正文清理代次的短暂重连保留已显示消息，换代、撤权清理和登出仍清除；独立浏览器仍只呈现订阅期间的内容；桌面原生面板会读取选中会话的历史页。


## DSH 原生会话面板（2026-10-31）

桌面单会话复用 DSH `conversation.content` 的 embedded 实例，使用同一宿主的 SessionProvider、聊天渲染器、Lexical 输入框、轮次导航和流式展示。Marshal 只保留设备/会话选择、云端身份验证以及 Agent 工作群；群聊的主持、派工与汇总保持原实现。

- 每个视图持有独立的 `marshal-view:` 命名空间会话，仅用于展示。原始目标仍由 deviceId + agent + sessionId 三元组确定，发送和停止回到原机器原引擎；不复制原始日志、不新建 DSH 后端会话、不把 Codex/Claude 改为 DeepSeek 模型。
- 当前安装的 DSH 0.2.1-rc.5 没有公开的外部会话注册接口。因此适配边界只替换自己新建的展示 Session 实例的 transport，并检查所需方法。全局原生 transport、其他会话和 Agent 工厂保持不变；宿主升级后需复验。未知接口形状拒绝加载。
- 历史经过独立的 `history.result` 帧返回，绑定命令、设备、智能体、会话、连接与 nodeEpoch。内容照常脱敏，过滤提问卡片和非目标内容；它不写入命令 journal、命令状态缓存或 SSE 环形缓存。读历史不 acquire/resume/prompt。
- 初次读取一页，更多历史通过按钮分页；页面显示未完整提示。DSH 按原生日志向前翻页，Codex/Claude 按各自只读接口顺序读取。过大的单页拒绝并给出 result-too-large，不截断后冒充完整历史。
- 续聊支持文本、图片和文件附件，以及模型与思考强度选择。权限切换、原生分支仍未映射；停止仍受原引擎能力及运行时代次检查约束。
- 桌面父页面只与已验证的 HTTPS Hub iframe 交换固定 MessagePort 消息。iframe 只接受 `dsh-app://app` 父来源；管理令牌和 cookie 不跨到宿主页面，所有写入仍通过原有 CSRF、所有权、同步屏障及持久幂等路径。
- 构建 `client/native.js` 与 `client/panel.js` 后生成单一 `client/index.js`；不另行打包 DSH/React，不重新声明宿主已有的普通 slot。每次历史替换清理先前投影，退出或切换会话释放持有引用。

验收：780 项测试、构建和测试类型检查通过；本机与第二台 Mac 的 Codex 原会话真实续聊均能引用先前标记，本机 DSH 在独立空目录的新测试会话里连续两次原生面板发送成功。DSH 业务会话仅用于只读历史显示检查。两机与云端 v13 的客户端、同步模块和页面文件 SHA-256 一致；未重启 DSH 宿主。Claude 的真实模型调用尚未验证，仍需完成认证。


## 模型、附件与名称

模型目录来自目标运行时：Codex `model/list`、Claude Query `supportedModels()`、DSH `modelCatalog()`。选择在下一次发送时应用；Codex 使用 `turn/start` 的 model/effort，Claude 使用同一 Query 的 setModel/applyFlagSettings，DSH 使用原生 selectModel（与原生界面相同，会记住默认选择）。界面显示“已选择”，不把请求值伪称为原引擎确认的当前值；权限不随模型切换改变。

附件最多 8 个、单个 10 MiB，按 192 KiB 分块经 TLS 中心转发，校验完整 SHA-256 后保存在目标 Mac 的独立临时目录。回执绑定操作者、设备、智能体、会话和节点代次，有效期一小时；切换会话清除未发送的附件。传输正文不进入命令 journal；图片走各引擎原生图片输入，其他文件以路径附件供原引擎按原有工具权限读取。文件不会因发送成功立即删除，以供当前会话后续读取；系统临时目录清理后需重新上传。

原生标题（缺省为首条消息摘要）仅在 privacy=content 且 allowContent 时同步，并经过已有脱敏。设备旁的编辑按钮通过经过认证/CSRF 验证的 device-name API 保存名称；身份、token 与授权修订号不变。中心为部署在 hub.example.com 的 Hub，负责认证、索引、命令/附件中转及工作群协调；实际模型调用与工具执行仍在会话归属 Mac。

本次验收（v17）：793 项测试、构建及测试类型检查通过。两机 Codex 均以实际 `gpt-6-luna / low` 完成调用：本机从界面上传图片并正确识别左右颜色；第二台通过中心接收 378,031 字节的分块文件并读回首行标记。本机 DSH 使用原生模型选择并读回附件标记。设备改名经界面保存后，在中心服务重启后仍保留；测试名称已恢复。标题检查时本机 259 条、第二台 70 条会话均有标题。所有实测都使用独立测试会话，没有向业务会话发送消息。

Claude 控制握手可能先于 `system/init` 完成，空输入时后者会等到首条用户消息才出现。新建接受原生 SessionStart 生命周期帧确认的身份，并要求认证握手完成；恢复则在只读清单确认原会话后，依据 SDK `resume` 的原 ID 契约建立路由，显式标明身份来自 `resume-contract` 而非伪造 init 事件。后续原生 init 身份不一致立即关闭；fork 不能拿父会话 ID 代替新会话 ID，未完成握手始终拒绝。此路径已在本机实际创建、取得模型目录并提交图片请求，重载后旧会话接管与模型目录读取也通过；上游返回订阅无效或已过期，不能列为模型回答成功。第二台 Claude 仍未登录；未修改任一机器的模型服务账号或订阅。

## Codex 思考强度与统计（2026-11-01，v22）

- 模型目录读取 `model/list`，当前模型/强度只读回查 `thread/read`。桌面选择“沿用会话模型”时也可选择该模型的思考档位，实际发送仍通过 `turn/start.effort`，不修改其他会话或权限。
- Codex 长会话改用 `thread/turns/list(itemsView=notLoaded)` + `thread/items/list` 分页，每页最多 20 条原生条目；跨页保留回合边界。原来 20 个完整回合可产生超过 10 MB 的单行响应并关闭传输。异常通道现在由监督器重建，已有写操作不自动重发；单条或投影页超过安全上限仍明确拒绝。
- 用量来自原生 `thread/tokenUsage/updated`；历史会话从原生返回且属于 Codex sessions/archived_sessions 的日志路径最多读取末尾 2 MiB。只同步数值，不上传日志路径或原文，不扫描内部数据库。选中会话按已有周期同步更新，可能有数秒延迟。
- 累计 token 不重复计算缓存，展示缓存命中和上下文占用。速度标为“平均 tok/s”：最近有完整基线和耗时的回合输出增量 / 原生回合总耗时，包含思考、工具和网络时间。原生没有可靠纯解码时间；历史尾部缺少完整回合证据时不编造速度，后续完整回合会补齐。

验收：构建、测试类型检查与 820 项回归通过；两个 Mac 的隔离 Codex 会话都完成 low/high 两次真实调用，原生回读的模型和强度一致；云端接口可读取两机统计。桌面“沿用会话模型 + 高”（本机）及“沿用会话模型 + 低”（第二台）发送都成功穿过中心服务并返回验证标记。两端仅热更新插件，DSH 宿主未重启，未向业务会话发送测试消息。
