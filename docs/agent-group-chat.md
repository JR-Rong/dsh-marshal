# 主持式 agent 群聊

2026-10-31 实现的 `discussion-moderated-v1`。插件内「调度官 → Agent 群聊」选择 2–4 个设备/平台/模型成员，指定其中一位主持人，选择「执行工作」或「仅讨论」，填写任务并预览范围后启动。

每轮由主持人生成分工，所选成员分别回复，主持人自动汇总。补充一条新消息会组织下一轮；每群最多 3 轮，最多 `(成员数 + 1) × 3` 次原生调用（2 人 9 次、4 人 15 次）。主持人可以只选择部分成员参与；未被分配、失败和取消的成员不代表赞同。分工解析失败会停止本轮，不猜测成员或自动重试。

工作群由主持人分工、Codex 执行成员在各自指定的现有项目目录内修改文件和运行命令，最后主持人汇总结果。DSH 可以主持工作群或参与纯讨论；尚不提供 DSH 原生工具执行成员。每个执行成员的项目绝对路径随预览摘要冻结，主持/汇总阶段仍无工具。讨论模式仅做文字分析，不恢复或导入任何工作会话。Claude 暂不作为群聊成员开放：缺少已认证且可验证的精确模型与隔离配置。

## 实现与边界

- DSH：使用宿主 `llm.prepareCall()` 的单次调用，传入精确 provider/model 和空 tools；不挂载 Agent/AgentLoop、工具调度器、工作区、会话 hooks、MCP 或子 agent。
- Codex 讨论/主持阶段：要求原生 0.166，使用私有临时 CODEX_HOME、空工作目录、单独 app-server、ephemeral thread、read-only sandbox。只临时复制本节点已有认证文件，不复制全局配置、技能或工作历史；退出后等待子进程结束再清除本次临时目录。
- Codex 讨论/主持阶段冻结模型目录：禁用 shell、apply_patch、搜索、扩展工具和多 agent；禁用工具及其他布尔 feature。原生 0.166 配置 schema 与模型目录行为共同约束工具集，不只依赖提示词。未知工具事件会中止。受控原生 provider 探针验证请求 `tools: []`；真实调用另行验证。
- Codex 工作阶段：同样使用私有临时运行时，只开放 shell/patch，使用原生 workspace-write 沙箱，禁止网络与提权，不继承用户 MCP、技能和 shell 环境凭据。输入目录必须存在，根目录、用户主目录及凭据目录被拒绝；同一节点上真实路径重叠（含符号链接别名）的群工作调用互斥。单会话/外部终端不在该互斥范围内。
- 工作结果附源端命令完成事件、退出码和 patch 文件记录；shell 写文件可能不出现在 patch 清单中，应结合命令与成员报告。停止先中断准确原生回合，再结束进程组；不回滚已经完成的文件修改。
- 凭据不会发给 Hub 或其它成员。模型服务仍按各自服务规则处理输入；临时 Codex 认证刷新不回写用户原始认证文件。
- 主持/讨论调用最多 120 秒，执行调用最多 10 分钟。讨论正文最多保留 15 分钟，工作群 60 分钟。输入最多 64 KiB、每条输出最多 16 KiB；累积上下文超限会停止分发，提示新建群聊。
- `allowDiscussion` 必须在节点配置和 Hub 设备策略两端打开。工作调用还必须经过有目录范围的工作模式预览，不能由讨论提示词升级；不必打开普通工作会话的 `allowContent`，普通 privacy/交互设置保持原样。

## 调度、幂等和恢复

浏览器使用现有 cookie 登录与 CSRF/Origin 校验。群聊 API 拒绝裸 token 操作；普通 `/api/command` 拒绝 `discussion.*`，避免绕过成员预览。预览摘要冻结材料、主持人、模型、设备代次和策略修订；启动前再次校验。群聊允许 owner 在明确预览范围内共享手动输入的内容。

Hub 将分阶段调用的元数据及幂等键先落盘，再通过现有认证 WSS 和节点 journal 调用 `discussion.turn` / `discussion.stop`。调用接受不等于完成；只有匹配当前连接、设备代次、群/成员/turn 且输出校验通过，才进入下一阶段。结果不确定时停止后续自动调用。

群聊正文只在 Hub 内存；标题、分工、发言和模型回复不进入持久元数据文件或 journal；工作模式及目录范围属于可恢复审计元数据。独立 `discussion.catalog` / `discussion.result` 帧不进入普通 EventBuffer、离线队列或工作会话历史。SSE 只发送变更提示，页面重新读取当前授权快照；页面不把消息正文保存到 localStorage/IndexedDB。

停止会取消本群正在运行的调用，不影响已有单会话；已经写入的工作产物保留。节点断线、本地重载、设备撤权或群内容到期后清正文并停止继续分发；调用结束未知时保留占额。调用超时且结果帧丢失会显示「结果待核对」。核对只查原命令状态，不重发模型输入，也不自动继续后续阶段。Hub 重启保留群/成员/调用元数据，正文不可恢复；旧群只能查看终止或未知状态，不会自动恢复推理。群聊存储损坏时只禁用群聊，普通会话服务继续。

## 流式回复与成员自定义设置（v25）

群聊使用专用 `discussion.progress` 通道传送带序号的完整快照，节点最多约每 200 ms 合并一次变化。DSH 的 text-delta 和 usage、Codex 的 agentMessage delta 与 tokenUsage 通知直接驱动预览；同一 Codex item 的完成文本替换其增量，不重复拼接。多个 commentary/final item 保留顺序。Hub 核对当前成员、设备、连接、turn、序号、字节上限和有效期；最终结果仍需原校验和通过。流式正文和临时用量只在内存，不进入 journal、持久元数据或离线回放。取消/失败保留已有部分并标注未完成，断线/到期沿用正文清除规则。

页面根据 SSE 变化合并刷新，不让连续事件取消正在进行的快照读取；只替换发生变化的消息卡片。未闭合围栏代码块也可预览。模型真实 usage 一到即更新，最终快照校准；模型暂未上报时显示明确标记的可见文本 token/速度估算（不含隐藏思考和工具，不混入已上报总量），不能用作账单或模型解码基准。
