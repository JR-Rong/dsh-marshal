# DSH 账号与私人调度空间

2026-11-01：当前版本支持复用 DeepSeek Harness 已登录账号，云端私人 Hub 绑定一个账号。两台已注册 Mac 进入同一个“我的调度空间”，无需手工输入管理 token。Agent 群聊是空间内的工作任务，可由主持分配、执行和汇总。

## 身份与凭据

DSH Host 的 `deepseekAccount.getPlatformSession()` 提供平台登录态。插件经校验 TLS 的连接，将原生平台授权临时交给用户自己配置的 Hub；Hub 只向固定的 DeepSeek 官方 `https://platform.deepseek.com/auth-api/v0/users/current` 查询当前身份。不会接受客户端自报的用户 ID 或身份验证 URL。账号键为官方 origin 与稳定用户 ID 的 SHA-256，必须与 Hub 已绑定账号一致。

平台授权只在本次验证请求内使用，不写入 Hub 配置、日志、journal 或浏览器。Renderer 只收到 60 秒有效、只能兑换一次的随机 Marshal 票据，再换取已有的 HttpOnly cookie；内嵌页面使用独立的 Partitioned cookie。保留 Origin、CSRF、登录限速和 TLS 校验。身份服务不可用时拒绝登录，不回退到匿名或旧的 token 表单。

插件打开时验证当前 DSH 账号，不直接恢复上次账号的页面。窗口重新聚焦及每 20 秒检查本机账号状态；退出或切换时清空原生展示会话、订阅和附件，并撤销当前调度登录。用户也可单独退出调度官，再点击“使用 DSH 账号进入”。正在执行的原生工作不会因为退出管理界面而自动取消。

## 配置与现有设备

Hub 配置 `accountLogin: true` 和 `dshAccountHash: <64 位账号摘要>`；节点配置 `accountLogin: true`。账号摘要必须由部署人员依据已经核实的当前账号绑定，不允许公网首次访问者抢占。节点继续使用原有的设备 ID、各自的连接凭据、journal 和权限；修改登录入口不改变原有设备名称、会话标题、策略或任务记录。

当前是一个私人 Hub 对应一个账号，不是开放注册的多租户账号平台。不同账号不能登录此 Hub。新机器安装本包后在插件页面选择角色，默认“边缘主机”连接现有 IP 中心；使用已登录的同一 DSH 账号自动注册。公共 IP 证书无需逐机信任。勾选内容共享后允许会话正文和工作群，审批权限保持关闭。已经注册的设备持续属于此私人 Hub，DSH 账号退出不等于撤销设备；撤销设备应使用设备管理流程。运维用 `x-marshal-token` 与节点凭据仍保留在后台，普通用户无需复制或输入。

## 验收与恢复

- 自动测试覆盖官方身份校验、错账号、身份服务异常、无效输入、响应大小与并发上限、票据过期/重放、Origin、cookie 隔离和本机未登录状态。
- 两台实机分别通过 Host 账号交换、内嵌登录、设备及工作群读取、重复票据拒绝和退出撤销检查；同一账号摘要，两台设备同步完成。
- 真实测试证据：`~/marshal-evidence/dsh-marshal-account-20261101/`，只保存脱敏结果，不保存平台授权、票据或 cookie。
- 配置备份：云端 `hub.before-account-20261101.json`；两机 `cordis.patch.before-account-20261101.yml`。需要回退时一起恢复旧代码和配置，保持设备表、身份及 journal 不变。云端重启会失效浏览器会话，按原有隐私策略清除工作群临时正文；不会重发任务。

当前适配依据为已安装的 DSH 0.2.1-rc.5 Host 接口，并非公开稳定的第三方 SSO 协议；DSH 升级时应复测。若以后扩展为多用户服务，应改用面向第三方的正式身份授权协议并增加工作空间、成员、设备注册和所有数据路径的租户隔离，不能直接放开此私人 Hub 的账号限制。
